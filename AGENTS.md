## OVERVIEW

Portfolio for Raihanmd (Software Engineer & Web3 Developer) + Payload CMS 3 backend. Next.js **15.4.x** (PINNED — see Conventions), React **19.2**, TypeScript strict, Tailwind 3.4 + shadcn/ui (new-york), Bun. Scaffolded from create-t3-app 7.37.0. Heavy 3D hero (three.js + react-three-fiber v9/rapier v2). The `/projects` page reads published projects from Payload/Postgres on request; `/til` has a client-fetched feed. Other site copy mostly uses static constants.

## CONVENTIONS

- **Alias `~/*` → `src/*`** (T3 default). Never `@/`.
- **Imports**: inline `import { type Foo }` (consistent-type-imports, inline fixStyle). Unused vars: `warn` with `argsIgnorePattern: "^_"`.
- **ESM everywhere**: `"type": "module"`; `next.config.js`/`prettier.config.js` are ESM (top-level `await import("./src/env.js")`).
- **ESLint**: legacy `.eslintrc.cjs` (ESLint 8, `next lint`). Do NOT migrate to flat config. `ban-ts-comment` is off; `require-await` off; `no-misused-promises` on (event handlers exempt).
- **Prettier**: defaults only (double quotes, semicolons, 80 width) + `prettier-plugin-tailwindcss` (auto-sorts classes).
- **Tailwind**: `darkMode: ["class"]`, content glob ONLY `./src/**/*.tsx`. Dynamic classnames must go in the `safelist`. Uses internal `flattenColorPalette` (behind `@ts-ignore`) + `mini-svg-data-uri` for aurora/grid utilities — fragile against Tailwind upgrades.
- **shadcn**: new-york style, aliases `components: ~/_components`, `utils: ~/lib/cn`. Add components via `bunx shadcn add`.
- **Next is PINNED to 15.4.x**: Payload 3 peer range is `15.4.11 ≤ next < 15.5.0 || 16.2.6+` — 15.5.x is NOT supported. Do NOT bump `next`/`eslint-config-next` outside the 15.4 line (upgrading means jumping to 16.2.6+ in one deliberate move).
- **Design rules**: shadcn semantic classes only (`bg-muted`, `text-muted-foreground`) — no inline `style={{var(...)}}` or raw hex in components; 8-state interactive components; focus-visible distinct from hover.
- **Server code is Payload-only**: API routes belong to the `src/app/(payload)/` route group. `/projects` is a dynamic RSC that reads published projects through `getPayload`; `/til` is a static RSC shell with a client-fetched feed. `til/[id]` and its `opengraph-image` are on-demand dynamic RSCs that read Postgres via the fast `pg` pool in `src/lib/query-til.ts` (the modal keeps `getPayload`); both are `force-dynamic`, never touch the DB at build. The `Experience` component is an async RSC that fetches from Payload. No middleware, no server actions, no `"use server"` outside Payload's own internals.
- **Multiple root layouts** (Next.js pattern): NO root `src/app/layout.tsx`. `(site)/layout.tsx` renders the portfolio `<html>` (globals.css, Navbar, next-themes, SEO metadata) and `(payload)/layout.tsx` renders Payload's own `<html>` (`@payloadcms/next/css` + `custom.scss`). Payload's `RootLayout` emits its own `<html>`, so it MUST NOT be nested under a global root layout — that causes `validateDOMNesting`/hydration errors and leaks site CSS+Navbar into `/admin`. New top-level routes must go inside `(site)/` (or `(payload)/` for Payload). `suppressHydrationWarning` on `<html>` is intentional (next-themes).

## UNIQUE STYLES

- 3D hero: three 0.168 + `@react-three/fiber` v9 + drei v10 + rapier v2 + meshline + leva; `global.d.ts` declares `*.glb`/`*.png` and augments R3F's `ThreeElements` with `meshLineGeometry`/`meshLineMaterial` (v9 removed the global JSX namespace).
- Motion: `motion` (framer-motion successor) via `AnimateItem`/`AnimateFade` wrappers. `AnimateFade` owns child staggering; `AnimateItem` owns slide/fade item variants and supports `motionStyle="fade"` for opacity-only items. Use raw `motion.div` only as the keyed state wrapper inside `AnimatePresence` transitions, as in TIL and Blog result swaps. Do not recreate feature entrances with Tailwind `animate-in` classes.
- State: Jotai atoms in `src/atom/` (only game-development.ts) + local `useState` in features; `usehooks-ts` for window-size/boolean helpers.
- Dark/light via next-themes (`class` strategy); Geist fonts.
- **Horizontal overflow guards**: `body { overflow-x: clip }` in globals.css clips entrance animation and font-swap overflow while preserving page scroll position when Radix locks the body for a modal. Project and TIL dialogs have bounded heights and horizontal clipping. Code blocks keep their own `overflow-x-auto`.
- OG image constraints (`next/og`/satori): **woff2 and variable fonts (fvar) crash the bundled parser** and **webp images crash resvg** — the OG cards use static Archivo 400/700 and Source Serif 4 400 TTFs committed in `public/fonts/` plus `public/favicon.png` as a base64 data URL. `next.config.js` traces `next/dist/compiled/@vercel/og/**/*` into the standalone build (wasm/emoji/noto) — without it the route 502s in Docker.

## BLOG UI AND STREAMING CONTRACT

- Blog follows the same page frame as TIL: `max-w-6xl px-6 pt-16` outside, then a centered 672px reading column built with `Section`, `SectionHeader`, and `SectionContent`. Keep the heading, tabs, filters, article rows, and Series section content aligned to that 672px column.
- Initial page motion and async result motion are separate. Give the Blog header and the tabs/filter controls separate `AnimateFade` roots: the header starts immediately and the controls use `delayChildren={0.3}`. Never place streamed result rows under that parent variant context; Motion variants propagate through ordinary DOM descendants and previously added about 670ms of unintended delay to the first article.
- Keep the Blog shell visible while queries change. Put Suspense only around the article/series result slot and use `ContentListSkeleton variant="article"` as its fallback. Do not restore a route-level `blog/loading.tsx` that redraws the heading, tabs, or filters.
- Streamed Blog fallbacks and results use the same Motion abstractions as TIL: `AnimateFade` for stagger ownership and `AnimateItem` for every row. Do not add Tailwind `animate-in`/manual delay arrays to feature code. The earlier server-inserted whole-result Motion wrapper could remain at `opacity: 0` until hydration; Chromium measured a gap from skeleton disappearance around 933ms until article visibility around 1343ms.
- One logical loading state must have one visual owner and one placeholder identity. `BlogResultsTransition` lives inside the persistent client `BlogFeature` tree and keys `AnimatePresence mode="wait" initial={false}` by the query/view. It only fades the outgoing/incoming result layout; it never mounts another skeleton. TIL's single state owner and controlled skeleton exit remain the behavioral reference.
- Initial RSC streaming and later client navigation have different motion timing. On a hard `/blog` load, result rows use `skipInitialAnimation` so the Suspense fallback is replaced by fully visible content even under slow hydration. After the persistent transition boundary has mounted, Articles/Series changes use `deferUntilMounted`; its IntersectionObserver starts the existing `AnimateFade`/`AnimateItem` variants only when the new result is actually painted. Do not animate initial streamed rows from opacity 0: it recreates the skeleton-to-blank flicker.
- Skeleton geometry must match its destination. Article rows and Series sections need different fallback silhouettes. Keep real-row padding aligned with the fallback; `first:*` styles belong on siblings in the list, not on an element that is the only child of each wrapper.
- Blog and TIL share `src/_components/content-list-skeleton.tsx`; TIL uses `note`, Blog Articles uses `article`, and Blog Series uses a destination-specific `series` variant. `AnimateFade` gives skeleton rows a 60ms stagger, and Blog delays the first fallback row by 120ms. Loading placeholders replace only unresolved list content.
- `BlogViewTabs` gives Article/Series navigation immediate local active-state feedback and exposes Next's `useLinkStatus` pending state. Keep the server `view` prop as the reset key after navigation commits.
- Do not wrap the final Blog shell or either detail page in a whole-page `AnimateItem` after a loading fallback. The old wrapper made the fallback disappear while the final shell was still transparent. Header-only, filter-only, and result-row motion preserve the visual language without replaying static page chrome.
- Blog's `SectionContent` uses `pt-2`; this places its control region 8px higher than the original `pt-4` while retaining the shared Section spacing and 672px alignment.
- Series mode keeps a text-only 192px sticky directory at `xl` and a 672px content column. The directory uses `top-24`; on smaller viewports it returns to normal document flow above the series sections. Its label, links, and section headers use `AnimateItem motionStyle="fade"`; article rows keep the standard slide/fade item variant with a 60ms stagger and 120ms initial offset. Avoid an enclosing card around the directory.
- Blog and TIL standalone details share `ContentDetailNav` and `ContentDetailSkeleton`. Their page container starts at `pt-24`, the reading column is `max-w-3xl`, and the dashed muted card begins after the same 32px nav plus 16px gap. Keep static back links rendered during loading; skeletonize only fetched metadata, cover/content, and the share action.
- Blog and TIL OG images use the site's two type families: Archivo for interface/brand text and Source Serif 4 for editorial text. Use only the committed static TTF files in `public/fonts/` for Satori.
- Decorative absolute layers must use `pointer-events-none` on the covering wrapper, not only on a visual child. The Aurora wrapper previously covered the top half of detail pages and intercepted the real Back link even though its gradient child ignored pointer events.
- Reduced-motion support is incomplete: skeleton pulse and several CSS micro-interactions opt out, but `AnimateFade`, `AnimateItem`, keyed TIL/Blog Motion transitions, Dialog animations, and the Aurora animation do not yet use reduced Motion variants. Treat this as an open accessibility gap.

Do NOT `Number()`/`parseInt` a TIL id — `findByID` takes the raw string. New ids are generated in the collection's `beforeValidate` hook.
- **TIL slugs are date-based**: `YYYY-MM-DD` in UTC (matches `formatTilDate`), auto-generated by a `beforeValidate` field hook (`generateSlug` in `src/collections/tils.ts`) with `-2`/`-3` suffix on same-day collisions; unique index + admin read-only. Existing rows stay NULL until the backfill SQL is run, so lookups must (and do) fall back to id. Feed links use `/til/${slug ?? id}`; canonical/OG URLs use the slug when present.
- **TIL view counting is client-side + admin-only**: standalone `TilDetail` fires `POST /api/tils/:id/view` once per TIL per browser session (sessionStorage dedupe + 1.5s debounce, fire-and-forget) — modal opens are NOT counted. The collection endpoint (`src/collections/tils.ts` `endpoints`) increments atomically via raw SQL (`COALESCE(views,0)+1`) so views never touch `updatedAt` or create draft versions. It is rate-limited by an in-memory fixed window (20 hits/min per IP+TIL, 120/min per IP — 429 + `Retry-After` beyond that; IP from `x-forwarded-for`, single-instance Docker so per-instance state is fine). The `views` field has `access.read` requiring `req.user`, so it's hidden from the public REST/GraphQL API (feed etc.) but shows in the Payload admin sidebar + list view (`admin.defaultColumns: ["date", "slug", "views"]`). It is `admin.readOnly` and a `beforeChange` hook force-writes the live DB value on every update — admin edits can never reset the counter.
- **GOTCHA — admin reads VERSION SNAPSHOTS, not the live row**: with `versions.drafts`, the Payload admin (edit + list) fetches with `draft: true`, which resolves to the LATEST VERSION SNAPSHOT in `_tils_v` (columns `version_views`, `version_slug`, …) — NOT the live `tils` row. Direct SQL writes (view increments, slug backfill) only touch `tils`, so the admin kept showing 0 views / empty slugs while the DB was correct. Fixes: `incrementTilView` also syncs the latest `_tils_v` snapshot; the `beforeChange` hook writes the live views into new snapshots; and `scripts/sync-til-version-snapshots.sql` (run once) backfills the existing stale snapshots (`version_views` ← `views`, `version_slug` ← `slug` where `latest = true`).
- **TIL legacy id URLs are canonicalized**: the standalone detail page `permanentRedirect`s `/til/<id>` → `/til/<slug>` (308) when the doc has a slug, so crawlers/old shares converge on one URL. The modal (soft-nav only) does not redirect. TIL detail 404s render `src/app/(site)/til/[id]/not-found.tsx` (AuroraBackground + back link) instead of the default Next 404.
